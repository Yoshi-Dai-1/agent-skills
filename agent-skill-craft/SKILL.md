# Agent Skill Craft Protocol

Agent Skillの設計・執筆・監査・改修・検証における決定論的実行プロセスを定義する。

## 概要と前提

- **ドメイン非依存**: 事務手続き、文章作成、分析・意思決定、ファイル操作、システム開発など、あらゆる領域の業務プロセスに対応すること。
- **AIエージェント指向**: 人間向けの第三者解説文や客観表現を排除し、AIエージェントが直ちに行動に移せる直接指示文言のみで記述すること。
- **既存コンテキストの尊重**: 既にプロジェクト内に存在するコード、設定ファイル、正本データ、既存文書の構造を最優先で参照・継承し、重複や競合を発生させないこと。

## 段階的実行フェーズ（Phase Protocol）

### Phase 0: 目的・範囲・構造の分析 (Scope & Architecture Analysis)

1. **要件と目的の抽出**: ユーザーが求めているスキルが解決すべきタスク、前提条件、入力、出力を明確化すること。
2. **構成スケールの判定（段階的開示）**:
   - 簡易なタスク（数ステップで完結するもの）: 単一の `SKILL.md` のみで構成すること。
   - 複合的なタスク（詳細な規約、参照資料、検証コード等を伴うもの）: `SKILL.md`（概要・フェーズ手順）と `references/`、`scripts/`、`assets/` へ役割分離すること。
3. **用語統一定義**: 対象ドメインにおける重要概念・オブジェクト名の表記ルールを事前決定し、同義語・表記ブレによる混同を防止すること。

### Phase 1: プロトコル・リファレンス執筆 (Drafting Protocol)

1. **執筆ルールの適用**: 参照ドキュメント `references/00-foundation/writing-style-guide.md` および `references/00-foundation/spec-conformance.md` を読み込み適用すること。
2. **決定論的ロジック（Condition-Action & Fallback）の記述**:
   - 曖昧表現を排し、条件（If）と対となる否定条件（Else / Fallback）を完全網羅すること。
   - 時間軸や人間側の開発事情を排し、コンテキスト内の状態（State）のみで分岐させること。
3. **順次適用ターンの分離規約**:
   - 順序付きファイルを適用する場合、一括ロードによる適用漏れを防止するため、1ファイル適用ごとにコードを出力・確定させるターン分離プロトコルを記述すること。
4. **能力ベース（Capability-based）の抽象化**:
   - 特定のツールベンダー名や一特定の実装手法に固執せず、AIエージェントがその場の実行環境に応じて最適な手段を選択できる記述とすること。

### Phase 2: アセット・スクリプトの整備 (Assets & Tooling Setup)

1. **テンプレート配置**: 再利用可能なフォーマットが存在する場合、`assets/` 配下へテンプレートを配置すること。
2. **検証スクリプト作成・実行**: 自動検証が可能な領域について `scripts/verify-skill.py` 等を作成し実行すること。

### Phase 3: 自己監査と品質検証 (Self-Audit & Verification Protocol)

1. **静的構文・規約検証 (Layer 1)**:
   - スクリプト実行環境が存在する場合、`scripts/verify-skill.py` を実行し、YAMLフロントマター、相対リンク、禁止語句・曖昧表現の有無を静的検証すること。
   - 検出された違反箇所を自律的に修正すること。
2. **全件整合性自己監査 (Layer 2)**:
   - 参照ドキュメント `references/01-protocol/self-audit-checklist.md` を読み込み、作成・改修したすべてのファイルを再走査すること。
   - 表記ブレ、参照パスの不整合、未定義分岐がないか全件確認し、完全にクリーンな状態で最終出力すること。
