# 監査規律（Audit Protocol）

対象スキルの自己監査・レビューを実施するときの規律。**不備を検出すること自体ではなく、検出の主張のしかたと、反復の制御に関する規則**である。

## 1. 主張には証拠を添える

- 不備を主張する場合、**対象ファイルの現行の原文引用と行番号（`path:line`）を必ず添える**。引用を欠く指摘は採用しない。
- 引用は監査時点で読み込んだ現行ファイルから取得する。**記憶や以前の読み込み結果の文面を根拠にしない。** 直前の読み込み内容が当該行と一致するか、報告前に照合する。
- 機械走査（スクリプト・grep）で確認した内容は、そのコマンドと出力を添える。
- 判断（可読性・適切さ・一貫性など、主観が介在する判断）は、判断の根拠となる対象箇所を引用したうえで述べる。
- 人間の指摘は検証のきっかけとし、判定は一次資料に照らして行う。一次資料に適合する場合は修正し、適合している場合は維持し、いずれも理由を添えて報告する。一次資料に反する指摘には従わない。利用者の意図・範囲の指示は利用者が最優先であり、この限りではない。
- 一次資料は事項に応じた一次資料とする。言語事項は内閣告示・内閣訓令・文化審議会建議・国語分科会報告・答申および法令用字に関する公的基準とし、列挙にない資料は一次資料として扱わず、台帳に記録して人間が判断する。スキル仕様事項は Agent Skills 公式仕様とする。競合する場合は対象事項の一次資料を優先する。
- 統一語を定義するファイル自身が統一語に従っていることを確認する（定義ファイルの自己適用確認）。

## 2. 未決済台帳（Ledger）で反復を制御する

- 監査を開始する時、まず未決済事項の一覧（台帳）を作成する。各事項に通し番号を付け、ファイル、箇所、種別、状態、根拠を記述する。
- **以降の監査報告は台帳の差分のみを出力する。** 決済済み（修正済み・誤り・該当なしと確定済み）の事項を再掲しない。**ただし最終報告だけは例外とし、決済済みの不備も「検出した不備」に含める。** 途中の報告と最終報告の書式が異なるのはこの差だけである。
- 清算した事項は台帳上で状態を「closed」にし、理由を記録する。台帳は `scripts/audit-ledger.py` で管理する。
- 台帳ファイルは**対象スキルとは別の作業領域**に置く。既定の置き場所は対象スキルと同階層の `ledger.json` である。対象スキルのディレクトリ内に置くと、対象スキルの成果物に混入するため、別の領域が望ましい。
- **台帳が管理する対象は、監査で検出した不備と、出力評価で残った未解決事項の 2 つである。** 両者を同じ台帳に置き、区別の種別で管理する。
- 台帳が空（未決済ゼロ）になった時点で監査を終了する。**終了条件を満たした後の再監査を禁止する。** 無限ループは監査の妨げになる。
- ただし、**修正を実施した後の再走査は禁止の対象外とする。** 再走査の対象は、その修正で決済した項目と、それによって新たに発生しうる影響範囲に限る。この再走査を新たな監査とは区別し、台帳に新たな未決済事項が生じないことを確認して終了する。

## 3. 検出なしの明言

- 走査の結果、不備が検出されなかった場合は、**「検出なし」と明示的に報告する。** 報告を省略しない。
- **「何かを見つけなければ」という圧力で見つからない問題を作らない。** 些細な表記差を不備として捻出しない。
- 使い分けとして正当な語差（意味の異なる対象を指す別語）は不備として扱わない。その場合は「対象相違による正当な使い分け」と明示する。

## 4. 多視点監査の運用条件

- 複数の観点（フローの分岐網羅性、スクリプトの精度、言語・表記など）を**互いに独立した担当者に委譲して並列に監査させる**手法は、誤検出の除外と未検出の補完に有効である。**この効果の測定条件は記録しない。** 実際の誤検出数と未検出数は、その回の台帳に記録する。再監査（同じ観点を別担当で再確認する）により、誤検出と未検出の両方を減らす。
- ただし費用が高いため、**大きな改修の確定前などの重要な局面に限定**して使う。日常の逐次修正ではコストが割に合わない。
- サブエージェントの監査で得られた指摘は、**依然として 1 節の証拠規律で照合する**。サブエージェントの報告も引用なしの場合は採用しない。

## 5. 機械走査と自己監査の分離

機械走査（検証スクリプトが行う）が判定できる項目は次の 9 つである。

1. フロントマター（必須フィールド、`name` 規則、description の長さ）
2. 構造（行数・token 予算・参照の深さ・参照の存在・未参照ファイル）
3. 参照グラフ（参照ファイル間の読み込み指示の循環と逆方向）
4. スクリプト要件（`--help`・終了コード・`--dry-run`）
5. 言語混在と仮名書き（文字化け・基準言語と異なる言語の埋め込み・仮名書きすべき語の漢字使用）
6. 語彙の混在と定義表・正本の一致（語族・`distinct_terms` の表と正本の照合を含む）
7. 評価データ（必須フィールド・`split` 値・クエリ数）
8. 正本との整合（記述の数値と正本データの一致）
9. 記述の重複と矛盾の候補

上記以外（対象文書の基準言語における自然さ、設計の妥当性、指示の妥当性、引用の正確性、意味論的整合）は機械では判定できないため、自己監査でレビューする。基準言語が日本語でない場合、言語固有の基準はその言語で定める。検証スクリプトの組込みの設定（`ja`、`en`、`fr`、`zh`、`ko`）は代表例であり、言語の種類に制限は設けない。正本は `scripts/validate-skill.py` の `BASE_SCRIPTS` とする。

- 機械走査と自己監査の守備範囲を混同しない。**機械で素通りした項目を「合格」と表示しない。** 検証手段の守備範囲外の項目は「対象外」と明示する。
- **機械走査は証明ではない。** 機械走査が見逃した項目は存在し得る。機械走査の通過を以って品質が保証されたと判断しない。

## 6. 修正の順序

1. 検出した不備を台帳に登録する（証拠付き）。
2. **同一の根本原因に紐づく不備をまとめて修正する。** 個別文面の表面修正を先行させない。表面修正は次の監査で再発する。
3. 修正後、該当箇所を再走査して、修正が実際に当該箇所に及んだことを確認する。
4. 台帳を清算し、監査報告する。監査報告の構成は「検出した不備（決済済みを含む）」「未決済の残存」「対象外（検証手段の守備範囲外）の項目」の 3 区分とする。
   対象スキルの**実行時の完了報告**は別の様式であり、`references/execution-protocol.md` の 4 節の 4 区分（変更点・解消・確認・残存ギャップ）を使う。2 つの様式を混ぜない。
5. 報告において、**実施していないことを実施したように記述しない。** 対象の範囲（何件中何件）、省略した手段と理由、検証できなかった項目を明記する。

## 7. 機械走査の既知の限界

`scripts/validate-skill.py` の検証には、原理的な限界がある。**この節は、検証の精度を過大に信じないための説明である。**

| 限界 | 補い方 |
|---|---|
| 言語の混在の主判定は区切り構造（引用として明示された連続塊は許可する）である。区切りがないが行全体が異言語の場合、引用か埋め込みかを機械では区別できない | 引用として明示されていない行全体の異言語は「warning」とし、自己監査で意図を確認する |
| 基準言語で使わない字形・語は、語リストがないと検出できない | 語リストを `assets/foreign-tokens.json` で拡張する。並列の独立監査で拾う |
| ラテン文字を主用しない基準言語では、許容語リストにないラテン語を言語の混在とみなす。リストにない正当な語は誤検知となり、リストにある混入は検出できない | 許容語リストを `assets/foreign-tokens.json` で拡張する |
| 語彙の統一は、語族を 1 度定義した範囲での混在しか検出できない。語族にない別語は検出できない | 語族を `assets/vocabulary.json` で拡張する |
| 語族の照合は原形の部分文字列で行うため、活用形（使った・用いたなど）は検出できない | 定義・記述は原形を使い、疑義がある場合は自己監査で確認する |
| `evals/` 配下およびその複写元のクエリ値は利用者発話の模写であり、パス・技術語・誤字を含むことが正当なため言語の検証の対象外とする | 構造は `check_evals` で検証する |
| 仮名書きの判定は副詞・接続詞の確実な語に限り、熟語・固有名詞は対象外とする | 対象語と推奨形は検証スクリプトの表で管理し、疑義がある場合は自己監査で確認する |
| 公式基準自体が例示の列挙であり、網羅のリストではない。例示にない語の仮名書きは機械では判定できない | 同類の規定に照らし、疑義がある場合は台帳に記録して人間が判断する |
| 設計の妥当性・基準言語における自然さ・引用の正確性は検証対象外 | 自己監査でレビューする。Layer B で行う |

**結論として、機械走査は「機械で判定できるもの」の層だけが対象であり、残留するものは自己監査でレビューする。** 両者を省略すると、機械で判定できない領域が検証されないまま残る。
