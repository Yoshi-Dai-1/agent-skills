# 語彙表（Vocabulary）

本スキルと、対象スキルの作成および監査で使う語を 1 つに定める。**同一の対象には同一の語を使う。** 異なる対象を指す語は、意味を区別して明示する。

## 1. 意味論的役割語

| 語 | 定義 | この語を使う文脈 |
|---|---|---|
| **AI エージェント** | スキルの指示を実行し、その指示に従って判断して作業する主体 | 指示文の主語。実行時の判断者 |
| **サブエージェント** | クライアントが別セッションで起動する独立した AI エージェント | 委譲して並列に監査させる場合 |
| **クライアント** | スキルを実行する AI 製品・実行環境。AI エージェントの動作基盤 | 実行環境・観測手段を指すとき |
| **利用者** | スキルを使い、指示を出す人間 | 利用者への確認・承認・提示・結果提示 |
| **読み手** | 生成された成果物を読む対象（利用者・後続の処理・別のシステム） | 成果物の文体の決定 |
| **人物** | 指示を出し成果物を読む個々の人間 | 利用者と読み手の同一性の説明に使う |
| **対象スキル** | 作成・監査・改修の対象となる Agent Skill | 参照先・所有者のスキル |
| **作者** | 対象スキルの指示を書く主体（AI エージェントまたは人間） | 執筆・改修の文脈 |
| **人間** | AI・機械に対する人間一般を指す総称 | 役割を指さない場合。役割は利用者・読み手・作者を使う |
| **読み込む** | 参照ファイルの内容を実行中の文脈へ取り込むこと | スキルが `references/` 配下のファイルを開くとき |
| **読む** | 記述された内容を理解すること | 文書や成果物の内容を解釈するとき |
| **検証スクリプト** | 機械的な検証を行うプログラム（`scripts/validate-skill.py`など） | 検証スクリプト自体を指すとき |
| **機械走査** | 検証スクリプトが行う機械的な走査 | 機械が行う検証の総称として使うとき |
| **自己監査** | AI エージェントが行う証拠付きの監査（Layer B） | AI エージェントが行う検証を指すとき |

### 1.1 「AI エージェント」の範囲

「AI エージェント」は製品名や規格名ではなく、**指示を実行する AI の実行主体**を指す語である。実行主体の形態（チャット型・コーディング型など）にかかわらず同じ規則を適用する。実行できない操作は「手段がない」として、省略の規定と報告義務の対象になる。**対象スキルの `description` にも、実行環境を特定する語を書かない。**

### 1.2 「利用者」と「読み手」

「利用者」は指示を出し「読み手」は成果物を読む。**同一の人物が両方を兼ねるため、語は分けるが人物は分けない。** 機械が利用者として指示を出すことはない。成果物の読み手が機械の場合は「読み手」と書く。

### 1.3 「読み込む」と「読む」

ファイルを取り込む操作には「読み込む」を、内容を理解する操作には「読む」を使う。**同じ文で混ぜない。**

## 2. 統一語と禁止する表記揺れ

機械可読な正本は `assets/vocabulary.json` の `term_families` である。各家族は「同じ対象を指す別語の集合」であり、**家族から 2 種類以上が同時に現れることが違反**である。**家族は語族を構成する個々の集合を指し、語族はその総称としての仕組みを指す。** 家族を 1 度定義すれば、禁止形を漏れなく列挙する必要はない。下の表と同じ内容の家族を保つ。この統一は正誤の判定ではなく、表記ゆれ防止の運用である。禁止形が誤りである意味ではない。

| 統一語 | 禁止する表記 | 禁止の理由 |
|---|---|---|
| 利用者 | ユーザー／依頼者／利用ユーザー | 同一対象を指す 4 語。同じものを指す語を増やさない |
| 読み込む | 読込む／読込 | 表記ゆれ。送り仮名の基準に照らして「読み込む」に統一 |
| 使う | 用いる／使用する | 表記ゆれ。「使う」に統一 |
| 発動 | 発火／活性化／活性度 | 同一対象を指す 4 語。「発動」に統一 |
| 検証 | 検査 | 「検証」に統一。基準との比較により適合かを判定する行為 |
| 記述 | 記載／記載する | 「記述」に統一。文書へ文言を残す行為を指す |
| スキル | 技能 | 「スキル」に統一 |
| AI エージェント | AIエージェント／AI アシスタント | 表記ゆれ。空白の有無で統一する |
| 検証スクリプト | 検証器／検出器／混入検出器／検査器 | 同一対象を指す 5 語。「検証スクリプト」に統一 |
| 機械走査 | 機械検証／静的検証 | 同一対象を指す 3 語。「機械走査」に統一 |
| 文化審議会建議 | 建議 | 同一対象を指す 2 語。「文化審議会建議」に統一 |

**「自動」は実行主体が機械（スクリプト・プログラム）である場合だけ使う。** AI エージェントの行為には使わない。「自動的に生成する」のように実行主体が不明な「自動」は、実行主体を明示する形に書き換える。

## 3. 意味が異なるため併存させる語

以下は対象が異なるため同一の語にしない。各定義を本表に置き、参照する文書では省略しない。

| 語 | 意味 | 使い分け |
|---|---|---|
| 検証 | 基準との比較により適合かを判定すること | 判定の根拠が基準との比較 |
| 確認 | 状態が想定どおりかを確かめること | 判定の根拠が観察 |
| 実行 | 手続きを動作させること | 動作の主体として使う語 |
| 適用 | 規則を効かせること | 規則の対象として使う語。「適用範囲」はこの意味 |
| 修正 | 判明した不備を是正すること | 変更の量が小さい |
| 改修 | 構造や設計を変更すること | 変更の量が大きい |
| 改稿 | 稿を改めること | 執筆物の文章の改訂。構造の変更は改修 |
| 完了条件 | 1 件の作業の終了を判定する基準 | 作業の側の基準 |
| 終了条件 | 反復を止める基準 | ループの側の基準 |
| 適用範囲 | 対象スキルの手法が及ぶ領域 | スキルの側の線引き |
| 範囲外 | 適用範囲に含まれないこと | 対象スキルの線引き |
| 対象外 | 検証手段の守備範囲外であること | 検証手段の線引き |
| 規律 | 本メタスキルの規則 | メタスキルの側の語 |
| 規約 | 対象スキルの既存規程 | 対象側の語 |
| 実行時 | 対象スキルが実際に動作する場面 | 実行時規律 |
| 作成時 | 対象スキルの記述を組み立てる場面 | 執筆・改修 |
| 明記する | 読み手に向けて明確に書き示すこと | `SKILL.md` 本文などの指示文での明示 |
| 記述する | 散文として書き表すこと | 条件節・報告文などの執筆 |
| 記録する | 台帳などの記録媒体に書き留めること | 台帳への状態・理由の保存 |
| 書く | 文字を書き記す行為一般 | 一般動詞として使う。執筆の意味では記述する |
| 形 | 具体的な現れ・ありさま | 伝わる形など、現れを指す場合 |
| 形式 | 決まった型・フォーマット | 出力形式・スキーマ・文体など、型を指す場合 |

## 4. 表記の基準

以下は対象文書の基準言語が日本語の場合の基準である。基準言語が日本語でない場合、同等の基準（表記の揺れを防ぐ規則）をその言語で定める。

- **基準言語**: 対象文書全体の主たる言語を 1 つ決める。本スキルの基準言語は日本語である。言語の種類に制限は設けない。検証スクリプトの組込みの設定（`ja`、`en`、`fr`、`zh`、`ko`）は代表例であり、制限ではない。設定がない言語は区切り構造のみで判定する。
- **引用の明示**: 基準言語と異なる言語の語を使う場合は、引用として明示する（引用符・コードスパン・独立行・括弧で囲う）。技術用語・パス・識別子はコードスパンで囲い、例示の外国語は許容語に登録して使う。**引用として明示されずに基準言語の文中に埋め込まれた異なる言語の語は、言語の混在として欠陥とする。**
- **仮名遣い**: 現代仮名遣い（昭和 61 年内閣告示第 1 号）とする。
- **送り仮名**: 送り仮名の付け方（昭和 48 年内閣告示第 2 号）の本則と例外に従う。判断に迷った場合は本則に従い、適用した本則・例外と参照先を台帳に記録する。多数決では決めない。
- **根拠の示し方**: 一次資料を示す場合は告示番号などの安定した識別子で示し、URLを書かない（リンク切れを避ける）。一次資料の範囲は `references/audit-protocol.md` 1 節の列挙で管理し、ここでは重複して列挙しない。判断に迷った場合の優先順位は、①本スキル内蔵の正本・語彙データ、②対象の用語規約、③外部の一次資料とする。③を使った場合は台帳に取得元と取得日を記録する。
- **振り仮名**: 常用漢字表（平成 22 年内閣告示第 2 号）の漢字を使う。読みが難しい表外字は使わない。やむを得ず表外字を使う場合は振り仮名を付ける。
- **外来語**: 外来語の表記（平成 3 年内閣告示第 2 号）の第1表を原則とする。固有名詞・技術用語は対象の用語規約に従う。
- **公用文**: 箇条書きの指示文は動詞を名詞化して「〜すること」で終止し、主語は省略する。禁止や条件を示す場合は「〜してはならない」を使う。否定の終止は「〜しないこと」または「〜しない」とし（文化審議会建議に両形の用例がある）、同一事項の反復では同一形を使う。条件節・理由文中の否定は「〜しない」とする。根拠は文化審議会建議の文体選択（見出し・箇条書きの文末は連体形で終わらせず「である・もの」などを付ける）による。法令条文の文末（「〜する」など）は対象外とする。
- **数値と単位**: 数値と単位の間の空白は全ファイルで統一する（例: 「1 行」「2 件」）。
- **例示の「など」**: 例示には「など」と仮名で書く。「等」は「とう」と読む場合に使う。助詞の前後に空白を置かない（例: 「ファイルの有無、モード、件数など」）。
- **括弧**: 日本語の文中の括弧は全角とする。コード・数式・固有名詞は半角とする。
- **句読点**: 日本語の文中は全角の読点「、」と句点「。」とする。
- **助数詞**: 漢数字とアラビア数字を混在させない。件数と回数はアラビア数字とする（例: 「3 回」「1 行目」）。
- **節の参照**: 節番号で示す。節名は「1 節」のように書き、節番号は参照先ファイル内で一意とする。

## 5. 機械チェック

語族の混在は `assets/vocabulary.json` に保持し、`python3 scripts/validate-skill.py <対象スキルディレクトリ> --vocabulary assets/vocabulary.json` で検証する。対象スキル内に語彙表は置かない（実行時の指示ではなく、未参照ファイルになるため）。対象ドメイン固有の家族が必要な場合は、監査時の一時ファイルとして作成・検証し、台帳に記録する。対象スキルが実行時に語の定義を要する場合のみ、対象の `references/` に最小限の用語定義を置く。

意図して使い分ける語の組は `distinct_terms` に理由付きで定義する。近似重複の警告のうち、差が宣言済みの使い分けだけのものは警告しない。類似度が中程度の文の組は語族の候補として提示するが、**機械は無断で語族に追加しない**。AI エージェントは各候補に推奨判断（追加・使い分け・保留）と理由および根拠（該当する公式基準の規定・用例）を添えた整理案を作成し、人間は採用・却下のみを判断する。承認された整理のみを適用し、理由を台帳に記録する。

語族は増やし続けない。監査のたびに使われていない家族がないか見直し、不要になった家族は整理する。家族の追加と整理の案はAI エージェントが作成し、採用・却下の判断は人間が行い、理由を台帳に記録する。

除外範囲は検証の種類ごとに異なる。語彙の検証では定義表の行だけを除外し、散文部は定義ファイル自身も検証する（定義ファイルの自己適用確認）。JSON の値は定義そのものであるため、`assets/vocabulary.json` と `assets/foreign-tokens.json` は語彙の検証の対象外とする。言語の検証では語彙データを保持する `assets/foreign-tokens.json` と、利用者発話の模写である `evals/` 配下を除外し、語彙表の日本語散文は言語の検証の対象にする。
