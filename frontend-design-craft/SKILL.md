# Frontend Design Craft Skill

ユーザーインターフェース（UI）の構築・監査・改修において、W3C ARIA APGのアクセシブル構造と指定デザインシステムの規約を適用するための決定論的実行プロセスを定義する。

## 概要と前提
- **既存コード優先継承**: 既存プロジェクトにおいては、正本ファイルの有無に関わらず、まず既存のコード構成（依存定義、スタイリング設定、既存コンポーネント等）をスキャン・解析し、確立されている技術スタックおよびスタイリング手法をそのまま継承・適用すること。

## 段階的実行フェーズ（Phase Protocol）

### Phase 0: 条件確定と環境・SSoT解析（Check Gate & Context Analysis Protocol）
1. **デザインSSoT（信頼できる唯一の情報源）の探索と継承**:
   - リポジトリ内からデザインSSoTファイル（例: `tokens.json`, `theme.json` 等のトークン定義ファイル）を探索し、存在する場合は正本として読み込み、トークン構造および指定スタイルを優先すること。
   - デザインSSoTファイルが存在しない場合は、既存のコード自体（CSS変数、Tailwind設定、テーマ定義ファイル等）を暫定的なSSoTとして扱い、スタイル構造をそのまま継承すること。
2. **デザインSSoTの遅延生成（Lazy Persistence）**:
   - SSoTファイルが存在しない状態で、以下のいずれかの条件を満たした場合に限り、`assets/token-ssot-template.json` の構造に従い `design/token-ssot.json` を新規作成すること。
     1. ユーザーから「トークン化」または「設定ファイルへの保存」の明示指示があった場合
     2. 既存コードに定義されていない新しい共通スタイル変数を追加定義する場合
3. **デザイン言語の識別・決定**:
   - ユーザープロンプト内にデザイン言語の明記がある場合は、その指定に従うこと。
   - プロンプトに指定がない場合は、プロジェクト内のCSS変数や設定ファイルから使用デザイン言語を識別すること。
   - 識別できず `references/01-design-system/` 配下に複数のデザインシステムフォルダが存在する場合のみ、選択肢を提示し人間に確認すること。1つのみ存在する場合は、確認を挟まずそれを自動決定すること。
4. **作業方針・適用レベルの確定**:
   - ユーザー事前指示で作業方針（保護優先 / ビジュアル適合 / 監査のみ等）が指定されている場合は、確認をスキップし即座に実行に移ること。
   - 指示が曖昧な場合のみ、作業方針を1行で人間に確認すること。
5. **コンテンツ・機能の保護**:
   - 既存画面のテキスト文章、見出し、説明文、フォーム項目、ボタン機能、UXフローを100%保持すること。

### Phase 1: 事前監査と具体的修正案の提示（Pre-Audit & Proposal Protocol）
1. **不適合箇所（ギャップ）の特定**:
   - コードを書き換える前に既存コードの不適合箇所（W3C ARIA APG構造、WCAG 2.2アクセシビリティ、指定デザインシステム規約）を特定すること。
   - デザインSSoTが存在しない場合は、プロジェクト内に未定義の独自クラス名や変数を直接出力することを厳禁とし、既存コードの記法に整合させた修正案とすること。
2. **修正案の事前提示**:
   - 「どの要素の何が不適合で、文章や機能を保護したままどう修正するか」を作業レベル（ユーザー指定レベル）に応じて箇条書きで事前に人間に提示すること。

### Phase 2: 連番規約ファイルの順次適用（Sequential Execution Protocol）
1. **連番ファイルのロード**:
   - 決定されたデザインシステムフォルダ（`references/01-design-system/` 配下の該当ディレクトリ）に存在する連番ファイルを番号順に検出すること。
2. **1ターン1ファイルの段階的適用**:
   - 最初の連番ファイル（`01-*.md`）を読み込み、該当規約に対するコードを出力・確定させること。
   - 次の連番ファイル（`02-*.md`）を読み込み、追加差分コードを適用・出力・確定させること（以降、全連番ファイル終了までターンを分離して順次繰り返すこと）。
   - 複数ファイルをまとめて読み込み一括出力することを禁止すること。

### Phase 3: 自動検証と自己修正（Verification Protocol）
1. **Layer 1 (静的コード検証)**:
   - スクリプト実行環境が存在する場合、`scripts/verify-ui.js` を実行し、WCAG 2.2基準（対比比率 4.5:1以上、タップターゲットサイズ 48x48dp以上）の検証結果を取得すること。
   - 規約違反が検出された場合、違反箇所に対応するコード改修案を生成し、該当ファイルを上書き更新すること。
2. **Layer 2 (描画視覚検証)**:
   - 実行環境に画面撮影および視覚認識ツールが存在する場合、ローカル画面キャプチャを取得し、「要素の重なり」「グリッドアライメントのずれ」「カラーコントラスト違反」の有無を検証すること。
   - 違反判定時はコード改修を行い、再キャプチャ・評価手順を実行すること。
3. **Layer 3 (完了報告)**:
   - 検証項目をすべてパスした後、変更点および解消されたギャップ一覧を整理して報告すること。
