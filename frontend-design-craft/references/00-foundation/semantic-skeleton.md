# Semantic Skeleton & Accessibility Guidelines (W3C ARIA APG)

## 0. 適用範囲
- 本ファイルはページ構造・命名・操作の正本とする。色・形状・書体の見た目は適用中のデザインシステムに従い、ここで定めないこと。

## 1. 必須 ARIA ランドマーク（Landmark Roles）
すべてのページ構造は、以下の標準ランドマーク要素で構成されなければならない（WCAG 1.3.1）。知覚可能な全内容はいずれかのランドマーク内に収めること。ランドマーク数は7以下を目安とすること。

- **`header` / `role="banner"`**: ページの主要ヘッダーおよびブランディング。全ページにひとつ。`article` / `aside` / `main` / `nav` / `section` 内の `header` は banner ではない。
- **`nav` / `role="navigation"`**: 主要ナビゲーションリンク群。（複数時の区別はラベル規則に従うこと）。
- **`main` / `role="main"`**: ページのプライマリコンテンツ領域。全ページに原則ひとつ。
- **`aside` / `role="complementary"`**: メインコンテンツをサポートするサイドパネル・補助領域。
- **`footer` / `role="contentinfo"`**: 著作権情報、補足リンク、ページフッター。`article` / `aside` / `main` / `nav` / `section` 内の `footer` は contentinfo ではない。
- **ラベル規則**: 同一ロール複数時は `aria-label` で区別し、ラベル名にロール名（「ナビゲーション」等）を含めないこと（「Site Navigation」と付けると「Site Navigation Navigation」と読まれる）。

## 2. ページ基盤（言語・タイトル・スキップ・見出し）
- **`lang` 属性**: `<html>` に内容言語を必ず宣言すること（例：`lang="ja"`）。読み上げ・翻訳・検索の言語判定がこれに依存する。言語が混在する区間は該当要素に `lang` を付与すること（WCAG 3.1.1 / 3.1.2）。
- **ページタイトル**: `<title>` にページ内容を特定できる題名を必ず付与すること（WCAG 2.4.2）。
- **スキップリンク**: ページ先頭に配置し、最初の `Tab` ストップで到達可能とすること。「本文へスキップ」で `main` へ移動させること（WCAG 2.4.1）。フォーカス時のみ可視化する方式でよい。
- **見出し階層**: `h1`→`h2`→`h3` の順序を飛ばさず付与すること。`h1` はページ主題ひとつ。見出しの拾い読みで全体像が掴めることを要件とする（WCAG 2.4.6）。

## 3. アクセシブルネームとキーボード操作
- **`<button>`**: 視覚的テキストが存在しないアイコンボタンには、必ず `aria-label` 属性で具体的アクション（例: `aria-label="検索ウィンドウを閉じる"`）を指定すること（WCAG 4.1.2）。
- **フォーム入力**: すべての `<input>`, `<select>`, `<textarea>` は `<label>` 要素と `id` / `for` 結合、または `aria-labelledby` で関連付けること。
- **画像**: 内容を伝える `<img>` には目的が通る `alt` を必ず付与すること（WCAG 1.1.1）。装飾専用画像は `alt=""` で読み上げ対象外とすること。
- **キーボード操作**: インタラクティブな全要素は `Tab` キーでフォーカス可能であり、`Enter` / `Space` キーで実行可能でなければならない（WCAG 2.1.1）。フォーカス順序は視覚順序と一致させること（WCAG 2.4.3）。フォーカスを閉じ込める場合は `Esc` 等の離脱手段を必ず用意し、トラップを作らないこと（WCAG 2.1.2）。
- **フォーカス可視**: `:focus-visible` の輪郭を除去しないこと。キーボード操作中の現在位置が常に目で分かることを要件とする（WCAG 2.4.7）。フォーカス位置が他要素に隠れないこと（WCAG 2.4.11）。
- **動的更新の通知**: 非同期に変化する状態・結果は `aria-live` 等で読み上げに伝えること（WCAG 4.1.3）。

## 4. ポインタターゲット最小要件（言語非依存の最低線）
- WCAG 2.2 SC 2.5.8 Level AA：ポインタ入力のターゲットは **24×24 CSS px** 以上とすること。例外として、中心に置いた直径 24px 円が他ターゲット・他の未達ターゲットの円と交差しない十分な間隔があれば適合（spacing exception）。文中のインラインリンク、等価な代替操作、ユーザーエージェント決定サイズ、必須の表示は除外。
- WCAG SC 2.5.5 Level AAA の目安は **44×44 CSS px** 以上。
- 視覚サイズを変えず hit area を広げること：`padding` 拡張、`min-width` / `min-height` 下限、icon-only は `::before { inset: -12px }` 等の透明拡張。
- 単一ポインタ操作の確定は up-event で行い、down-event での実行・キャンセル不能を作らないこと（必須の操作を除く）（WCAG 2.5.2）。
- 適用中のデザインシステムに本ファイルより厳しい定めがある場合はそちらを優先すること。
